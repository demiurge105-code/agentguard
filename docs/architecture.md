# AgentGuard — MVP Architecture

## Goal

AgentGuard is an open-source permission layer for AI agents interacting with crypto wallets.

The current MVP does not execute real transactions. It evaluates whether a proposed transaction is allowed according to an owner-created policy.

## Core flow

Policy owner
    |
    | POST /policies + owner token
    v
AgentGuard API
    |
    v
SQLite Policy Store
    |
    | policy_id
    v
AI Agent ---- POST /check-transaction
                    |
                    v
               Policy Engine
                    |
                    +---- Transaction limit
                    |
                    +---- Daily spending limit
                    |
                    +---- Allowed recipients
                    |
                    v
                 ALLOW / DENY

## MVP components

### Policy Engine

Responsible for evaluating transaction requests against a policy.

Input:

- transaction amount
- recipient address
- server-derived daily reservations for the current UTC day
- stored policy

Output:

- allowed: true/false
- reason_code
- reason

The engine remains independent of HTTP and database code.

### SQLite Policy Store

The storage layer is implemented in `agentguard.storage.SQLitePolicyStore`.

It provides:

- `create_policy(policy) -> policy_id`
- `get_policy(policy_id) -> Policy | None`\n- `evaluate_and_reserve(policy_id, amount, recipient, request_id) -> Decision | None`

The store creates its table safely when initialized. Policy IDs are generated by the server. Monetary values are stored as decimal strings, and recipient allowlists are stored as JSON. Each row also records a UTC `created_at` timestamp.

The database path is configured with `AGENTGUARD_DB_PATH`; the default is `agentguard.db` in the current working directory. Database operations are kept outside the policy engine.

### API

The FastAPI application is created by `create_app(store=None, admin_token=None)`. This allows tests to inject an isolated SQLite store and token. The module also exports `app` for Uvicorn.

#### POST /policies

Creates a policy. Requires:

```http
Authorization: Bearer <AGENTGUARD_ADMIN_TOKEN>
```

The token is read from the `AGENTGUARD_ADMIN_TOKEN` environment variable and is never accepted in the JSON body. If it is unset or empty, creation fails closed with HTTP 401. A successful response returns the server-generated `policy_id` and the normalized policy values.

#### POST /check-transaction

Accepts only:

- `policy_id`
- `amount`
- `recipient`
- `request_id`

The API loads the policy from SQLite and passes it to the existing policy engine. Policy overrides in the request are rejected. Unknown policy IDs return HTTP 404. A successful evaluation returns `allowed`, `reason_code`, and `reason`.

**Security limitation:** `daily_spent` is still supplied by the caller. A malicious caller can provide a false value, so the daily limit is not secure against that caller. Trusted persistent daily-spend accounting and concurrency protection are explicitly out of scope for this change.

### Decision Log

A future decision log may record:

- timestamp
- requested amount
- recipient
- decision
- reason

This is not implemented by the current policy store.

### Demo Agent

A small Python program will simulate an AI agent making transaction requests.

It will demonstrate both allowed and denied actions.

## Security scope

The MVP is a policy evaluation system, not a wallet security system.

It does not hold keys, sign transactions, submit transactions, or stop an agent from bypassing the API. The owner token is a shared secret for policy creation, not full user or agent authentication. Do not use the API as the sole control protecting real funds.

```text

    policy.py       Policy models and deterministic evaluation

tests/
    test_policy.py  Policy engine tests
```

## What we are NOT building yet

- Trusted daily-spending accounting
- Accounts, roles, or full authentication
- Policy update or deletion endpoints
- Token
- DAO
- Own blockchain
- Mainnet transactions
- Custody
- Trading
- Autonomous financial agents
- Complex cryptography
